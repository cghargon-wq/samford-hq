Owner's Guide — running the websites yourself

Everything runs itself. You never install anything, never edit code, and never call a developer. Every change follows the same two moves: 1) edit in HQ  2) drag one file onto the publish page. The websites rebuild themselves about two minutes later.

HQ works from any computer or phone. Your login unlocks the data — without it, the page is unreadable code. Check “keep me signed in” on your own computer and you won't be asked again.

One-time setup (15 minutes, ever)

  1. Make a free account at github.com — this is the “publish key” to the websites.
  2. Tell Geron your username. He adds you as a collaborator; accept the email invitation that follows.
  3. Get your HQ email + password from Geron. Sign in at the HQ link above.

Change wording, phone numbers, or “Available now” homes

  1. In HQ, open the Website tab. Type your changes — headlines, phone, hours, home descriptions, the gold “Available now” badge for each rental home.
  2. Click ⬆ Publish website changes. A small file lands in your Downloads and the publish page opens.
  3. Drag the file from Downloads onto the publish page, then press the green Commit changes button.
That's it. Give it two minutes, then refresh the public site and see your words live.

Mark stalls rented / vacant, change rents, tenant details

  1. In HQ, click any stall on the map (or any home). Toggle rented/vacant, fix a rent, update a phone number — revenue numbers recalculate as you click.
  2. When you're done for the day, press ⬆ Publish changes (bottom bar).
  3. Same move: drag the downloaded file onto the publish page → green Commit changes button.

Publishing updates the live availability map customers see AND makes your edits appear in HQ on every other computer, not just yours.

Quarterly: new Space Master workbook

  1. When Stacey's updated Excel arrives, make sure the filename still contains Space Master (it always does).
  2. Drag the .xlsx straight onto the publish page → green Commit changes button.

The system reads the workbook, refreshes every stall, rate, and tenant, and republishes all three sites by itself. A new workbook wins over old clicks: stall toggles you published earlier are replaced by what the workbook says, so re-do any toggle the workbook doesn't know about yet.

Monthly: expenses for the ledger

Export or type expenses into a CSV/Excel file using the template's column names (Date, Property, Category, Description, Amount) and drag it onto the publish page after opening the expenses folder there (or just ask HQ's Ledger tab to ingest it in-browser for a quick look).

If something looks wrong

  • My change isn't showing. Wait two full minutes, then hard-refresh (hold Shift and click reload). On a phone, close and reopen the browser tab.
  • The publish page says “commit failed” or looks scary. Just reload it and drag the file again — nothing breaks from retrying.
  • I forgot my HQ password. There is no reset link on purpose (that's the security). Geron can issue a new one.
  • I dragged the wrong file. Harmless — the system ignores files it doesn't recognize.
Two rules that protect you: never type customer card numbers anywhere in this system (payments stay with the card processor — this is the law of the platform), and never delete files on the GitHub pages — everything you need is drag-and-drop only.

What happens under the hood (for the curious)

Your dragged file lands in a private folder called intake. A robot (GitHub Actions) notices, rebuilds all three websites from the master ledgers, and publishes them. The tenant ledger itself is never public: the public sites show only stall numbers, sizes, rates, and open/full status, and HQ ships fully encrypted — your password is the only key.
